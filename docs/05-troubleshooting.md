# 5. Troubleshooting

Most failures fix themselves: a failed run is re-run once, then an agent tries to fix it, then you get an issue. These
are the ones that land on you, with what to do.

| You see | Why | Do |
|---|---|---|
| Every agent run fails within seconds, "refused" or "model not available" | The Claude plan changed and `--model best` picks a model the plan doesn't have | In `.github/actions/claude/action.yml`, set `--model opus`, release the machinery. |
| Agents fail with "usage limit", issues get `retry next week` | The Claude (or Copilot) quota is used up | Nothing: they retry on Monday. To retry now, take the label off. |
| A used-up quota is listed in Automation health as a failure, and the issue gets no `retry next week` | Claude or Copilot words its limit in a new way | Add the wording to `.github/scripts/out-of-credit.sh` and to its test, `test-scripts.sh`, and release the machinery. Meanwhile, add the label by hand. |
| An agent's comment says it ran out of time | It worked for an hour without finishing, or hung | Ask for less at a time, or call it again (`@claude ...`, or its label). If Copilot keeps hanging, bump its CLI: `cli-version` in `.github/actions/copilot/action.yml`. |
| Claude's answer says it couldn't run a command or write a file, and its run warns "Claude was refused tools" | Claude Code kept Claude from them: its commands run isolated, which needs `bubblewrap` and `socat` on the runner ("Sandbox dependencies not available"), or a new Claude Code asks for a permission the machinery doesn't give | The warning names the tools, the answer says why. In `.github/actions/claude/action.yml`: the step that installs the two, and `--allowedTools`. Release the machinery, then call Claude again. |
| Claude's answer says Gradle fails with "Read-only file system" | Claude's commands can't write the checkout's git hooks, and the build's settings wanted to write them: they changed in Claude's own commits, or couldn't be written before it started (a warning in its run says so) | Make the change to the hooks yourself (`gitHooks` in `settings.gradle.kts`), or fix what the warning's step reports, then call Claude again. |
| "Not the agents' to change" in an agent's run, whose commits weren't pushed | Its commits changed the agents' own settings (`.claude/settings.json`, `.mcp.json`, `.github/copilot/`, `.github/hooks/`) | Make that change yourself, if you want it. |
| "The branch moved" in an agent's publish job, whose commits weren't pushed | The branch got commits, yours or another request's, while the agent worked on it | Call the agent again (`@claude ...`, or its label): it starts from the branch as it is now. |
| "Bad credentials" or 401 in an agent or the bot's steps | A token expired or was revoked | docs/04-renewals.md. |
| "Not a maintainer: @someone can't call the agents" in Automation health | Someone without write access (a read-only collaborator or organization member) called an agent; it didn't run | Nothing. If they should, give them write access; or call the agent yourself. |
| The agent missed what someone wrote; its thread says "Left out: not a maintainer's" | Others' posts reach the agents only as they stood when a maintainer last called one, never posts or edits from after | Read the posts, then call the agent again (`@claude ...`, or remove and add its label). |
| "Resource not accessible by integration" in the bot's steps | The bot lacks a permission (after a machinery change that needs a new one) | The App's settings → Permissions → add it; then accept it on the installation (**`<owner>` Settings → GitHub Apps → Configure → Review request**). |
| A release went to neither Google Play nor TestFlight | `PLAY_TRACK` (or `APPLE_TEAM_ID`) isn't set on the app | Set it (docs/02-new-app.md, steps 8 and 10a): the next release uploads, and its notes include this one's. |
| Google Play upload fails with 403 | The service account lacks a permission on the app | Play Console → Users and permissions → `publisher@…` → App permissions (docs/02-new-app.md step 8). |
| Google Play upload fails with "Package not found" | The app isn't on Play yet, or `app.id` is wrong | Do the first upload by hand (docs/02-new-app.md step 7); check `app.id` in the app's `gradle.properties`. |
| Store listing fails with 403 | No **Manage store presence** for the service account | As above. |
| "The job was not acquired by Runner" on the iOS job | GitHub's macOS runners were busy | Re-run the job; it isn't a code problem. |
| The iOS UI test can't find the home screen | The app crashed or was too slow to draw | The run's `ios-screenshots` artifact holds a screen recording (`.mp4`) and the crash report (`.ips`). |
| "Upload to TestFlight" fails with "No profiles for ..." or a bundle identifier error | The app's id isn't registered with Apple, or the API key hasn't Admin access | docs/02-new-app.md step 10a; the key needs **Admin**. Then **Re-run failed jobs**. |
| The upload fails with "No suitable application records were found" | The app has no App Store Connect record yet | Make it (docs/02-new-app.md step 10a), then **Re-run failed jobs**. |
| App Store Connect won't send a version to review: "You must add the com.apple.developer.game-center key in Xcode" | The version's build lacks an entitlement a feature needs (Game Center here): the app doesn't name its entitlements file, or the build is older than it | Name the file in the app target's `CODE_SIGN_ENTITLEMENTS` (docs/02-new-app.md, section 12), release, and pick the new build on the version's page. The "Carry the app's entitlements" step of the TestFlight job lists what the archive carries. |
| "Upload to TestFlight" fails with "Cloud signing permission error" | The App Store Connect API key hasn't **Admin** access: only Admin keys reach the cloud-managed distribution certificate | Make a new key with **Admin** access (docs/01-once-per-account.md step 8), store it with `set-secrets.sh`, then **Re-run failed jobs**. |
| Apple emails "ITMS-91053: Missing API declaration" and the build never reaches TestFlight | The app's code, or a library's, calls an API Apple wants a reason for, and the app's `iosApp/App/PrivacyInfo.xcprivacy` doesn't declare it | Add the category the email names, with its reason, to that file (Apple's "Describing use of required reason API" lists them); the next release uploads again. |
| Upload fails with "a required agreement is missing or has expired" | Apple updated its Program License Agreement | The Account Holder accepts it in <https://developer.apple.com/account>, then **Re-run failed jobs**. |
| The App Store listing job fails with "no app with the bundle id" | The app has no App Store Connect record, or `app.id` isn't its bundle id | Make the record (docs/02-new-app.md step 10a), then **Re-run failed jobs**. |
| The App Store listing job fails with "can't go up" | A text of `store/app-store` is over Apple's limit, or a screenshot isn't a size Apple takes | The message names the file and the limit: shorten it, or fix the size in StoreArtTest. |
| The App Store listing job fails with 409 and `ENTITY_ERROR.ATTRIBUTE.INVALID` (or `...INVALID.TOO_LONG`, `...REQUIRED`) | App Store Connect refused a value: an id Apple renamed (a category, an age rating answer), a URL it can't open, a text it measures differently | The report names the field: change it in `store/app-store`. Every other step still ran. |
| The achievements step's report says "No Play Games project id" | The game's games services project isn't in its ids file yet | docs/02-new-app.md step 12: create it, put its id in the file. |
| The achievements step fails with 403 from Google Play Games | The service account hasn't the Play Games Services permissions on the app | Play Console → Users and permissions → the service account → the app's permissions. |
| The achievements step fails with 400 from Google Play Games | Play refused a value: a language it doesn't take for achievements, a text too long | The message names it: shorten the text, or leave the language out of that achievement's strings. |
| The achievements step's report says "the hourly limit of requests was reached" | A first run of many achievements in many languages: App Store Connect takes some 3,600 requests an hour | Nothing: the next run (the next release, or one by hand with **store-listing**) goes on from there. |
| The achievements step's report says App Store Connect "refused the achievements' texts in" a language | Game Center doesn't take that language | Nothing: it is left out, the others go up. |
| The achievements step fails with "can't go up" | The list breaks a rule (an id, the points, a text missing in the default language) or a picture isn't 512 or 1024 pixels square | The message names each problem: fix the list, the texts or StoreArtTest. |
| The App Store listing job fails with 403 | The API key hasn't **Admin** access | As for TestFlight: a key with **Admin** access. |
| The job's report says "Can't be sold in ..." | Apple's reason for each country (`TRADER_STATUS_NOT_PROVIDED`: the EU's trader status; `ICP_NUMBER_MISSING`: China) | docs/02-new-app.md step 10c, or exclude the country with `availability.exclude`. |
| The version being prepared has an older build than the release | App Store Connect took longer than `app-store-build-wait` minutes to process the new one | Nothing: the next release, or a run with **store-listing**, takes it. |
| A commit is refused by CI: "header must not be longer than 100 characters" | A commit subject over 100 characters (the local hook doesn't count them), or a pull request title that the " (#123)" of squash-merging took past 100 | Before merging: shorten it (a branch can't be force-pushed by the agents: open a new pull request from a rebuilt branch). After: nothing to do, since the next push checks only its own commits. |
| A release made nothing | Only `build`, `ci`, `docs`, `refactor`, `test` or `chore` commits since the last one | Expected: `feat`, `fix`, `perf` and `revert` release. |
| "What's new" stayed in English | No Claude token for the release, or the translation failed | The run's warnings say why. The next release translates again. |
| A scheduled job hasn't run at its hour (the Monday retry of the issues, the monthly refresh, an app's own cron) | GitHub starts scheduled workflows when it has room, which can be hours after their time; nothing in the app or in the machinery delays them | Wait, or start it by hand: **Actions → Automation → Run workflow**, with the task (`retry-issues` or `refresh`). |
| Settings drifted (a rule changed by hand) | — | **app-machinery → Actions → Self automation → Run workflow → settings** puts `settings/` back. |

When nothing here matches, open an issue in the app: the issue agent reads the logs and either fixes it or says what
you must do.
